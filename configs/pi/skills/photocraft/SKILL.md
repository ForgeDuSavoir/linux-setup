# PhotoCraft with Pi

- Help the user **learn the GUI first**: ask what they want to do, explain steps and terminology clearly, and inspect the live window and active document in read-only mode before making claims about their current layers or selection. Don't invent menu names, shortcuts, or commands; discover them if unsure. Ask before *any* edit, save, or export. Explain the intended change before executing it.
- `photocraft-ai [project.pcraft]` opens PhotoCraft and Pi together in a dedicated session; the `photocraft_live` bridge is enabled there and the headless `photocraft` server disabled. Verify the window and active document through live inspection tools (discover them first); an MCP connection by itself does not prove the GUI is running. Reopening a project resumes its conversation. A regular PhotoCraft window is **not** bridged. To open a controlled window without Pi, use `photocraft-live` and enable `photocraft_live` manually from another Pi session.
- Outside the dedicated Pi directory, `photocraft` is headless and enabled, `photocraft_live` disabled. Never assume a headless document appears in the GUI. Headless file automation is limited to `~/Pictures/PhotoCraft-AI`; use relative paths and work on copies. The assisted live app limits automation file access to the opened project's directory (or `~/Pictures/PhotoCraft-AI` when started without a project). This does **not** sandbox Pi's normal tools or prevent manual GUI edits; protect the original document and ask before saving.
- Discover tools in the appropriate `mcp__photocraft_live` or `mcp__photocraft` namespace using Pi's tool search/codemode and inspect their schemas before calling them. Typical tools include `doc_inspect`, `command_list`, `command_run`, `doc_save`, and live-only UI inspection. Use `command_list` before invoking unfamiliar command IDs; never open a second headless copy of the live document.
- Inspect document and layers before editing. When asked to save or export, confirm the destination and whether to overwrite anything; prefer a separate `.pcraft` copy. After saving, inspect the result. On a bridge timeout, inspect before retrying a mutating operation: the first call may have completed.
